# Periodic Quest 設計文件

日期：2026-08-23
狀態：已核可，待撰寫實作計畫

---

## 1. 目標

一個協助台灣國中生記憶元素週期表的軟體，跑在 Mac 與 iPhone 上。核心主張是：
**死背無效，要有記憶掛鉤（口訣＋圖像）、要有間隔重複、要有讓人想再打開一次的理由。**

五項功能需求：

1. 教記憶法 — 按族口訣（台灣繁體語感）與圖像聯想
2. 隨機測驗
3. 記錄弱點並自動排入複習
4. 遊戲化，主題致敬《排球少年》與 NCT WISH
5. 提供完整元素表與口訣的查詢介面，隨時可查、不受學習進度限制

兩項流程需求：

6. 版本控管
7. 開發過程受每日 token 額度限制，必須可隨時中斷、隔天無痛續作

## 2. 使用者

單一使用者：一位台灣國中生。喜歡《排球少年》與 NCT WISH。
主要在 iPhone 上短時間片段使用（通勤、下課十分鐘），偶爾在 Mac 上長時間練習。
沒有帳號、沒有多人、沒有家長後台。

## 3. 技術決策

| 決策 | 選擇 | 理由 |
|---|---|---|
| 平台 | 純 PWA（HTML/CSS/JS） | 環境無 Xcode、無 node。PWA 一份程式碼同時涵蓋 Mac 與 iPhone，加入主畫面後有全螢幕與離線能力 |
| 模組化 | 原生 ES Modules | 瀏覽器直接支援，不需要打包工具。拆檔讓 sub-agent 每次只讀單一小檔，直接節省 token |
| 資料儲存 | localStorage（設定與進度）＋ IndexedDB（學生自訂圖片） | 零後端、零帳號、零隱私問題。未成年人資料不離開裝置 |
| 跨裝置同步 | 不做 | 學生實際上固定用一台裝置練習。同步需要後端與帳號，成本與風險都不成比例 |
| 記憶法組織 | 按族（直行）口訣為主，個別圖像為輔 | 台灣國中生實際使用的方式；同族性質相近，記住直行等於順便記住性質規律 |
| 複習演算法 | Leitner 五盒 | 見 §6.2 |
| 測試 | 只測核心邏輯，瀏覽器原生執行 | 見 §9 |
| 部署 | GitHub Pages（學生使用）＋ `python3 -m http.server`（開發驗證） | 見 §10 |

### 已評估但否決

- **原生 SwiftUI**：體驗最好且可上架，但需先安裝完整 Xcode，且每次驗證都要 build，token 消耗過大，與需求 7 直接衝突。
- **單一 index.html 巨檔**：雙擊即開很誘人，但檔案膨脹後每次編輯都要付整檔的 token，且多個 sub-agent 無法平行工作。
- **SM-2 演算法**：見 §6.2。

## 5. 資料模型

### 5.1 elements.json

客觀事實，一次建置完成，內容不隨開發進度變動。

```json
{
  "z": 11,
  "symbol": "Na",
  "zh": "鈉",
  "en": "Sodium",
  "period": 3,
  "group": 1,
  "category": "alkali-metal",
  "mass": 22.990,
  "state": "solid"
}
```

`category` 列舉值：`alkali-metal`, `alkaline-earth`, `transition-metal`, `post-transition-metal`, `metalloid`, `nonmetal`, `halogen`, `noble-gas`, `lanthanide`, `actinide`。用於週期表著色與「同類干擾選項」。

### 5.2 記憶法：按族口訣為主，個別圖像為輔

**核心決策：主要記憶單位是「族」（直行），不是原子序（橫排）。**

這是台灣國中生實際使用的方式，也是教學上更好的方式——同一族最外層電子數相同、
化學性質相近，記住一整行等於順便記住性質規律。

#### 5.2.1 mnemonics-groups.json

八個主族的口訣，由使用者提供（來源見 §8.1），已逐字核對正確。

```json
{
  "group": "1A",
  "name": "鹼金族",
  "chant": "請你讓佳如設法",
  "mapping": [
    { "char": "請", "z": 1,  "symbol": "H",  "zh": "氫" },
    { "char": "你", "z": 3,  "symbol": "Li", "zh": "鋰" },
    { "char": "讓", "z": 11, "symbol": "Na", "zh": "鈉" },
    { "char": "佳", "z": 19, "symbol": "K",  "zh": "鉀" },
    { "char": "如", "z": 37, "symbol": "Rb", "zh": "銣" },
    { "char": "設", "z": 55, "symbol": "Cs", "zh": "銫" },
    { "char": "法", "z": 87, "symbol": "Fr", "zh": "鍅" }
  ],
  "scene": "一個叫佳如的女生站著想辦法",
  "sceneNext": "2A"
}
```

八族完整口訣：

| 族 | 名稱 | 口訣 | 元素 |
|---|---|---|---|
| 1A | 鹼金族 | 請你讓佳如設法 | 氫鋰鈉鉀銣銫鍅 |
| 2A | 鹼土金族 | 媲美蓋斯被雷 | 鈹鎂鈣鍶鋇鐳 |
| 3A | 硼族 | 朋屢嫁英他 | 硼鋁鎵銦鉈 |
| 4A | 碳族 | 嘆息著西遷 | 碳矽鍺錫鉛 |
| 5A | 氮族 | 但你身體病 | 氮磷砷銻鉍 |
| 6A | 氧族 | 楊柳溪地破 | 氧硫硒碲釙 |
| 7A | 鹵素 | 浮綠秀點鱷 | 氟氯溴碘砈 |
| 8A | 惰性氣體 | 害乃亞克先動 | 氦氖氬氪氙氡 |

`mapping` 是關鍵欄位：教學畫面靠它逐字高亮，「口訣填空」題型靠它出題與判分。

#### 5.2.2 場景串接

八族的口訣不是各自獨立的，而是串成一條連貫的故事線。這是原始素材最有價值的地方——
單獨記八組無意義音節很難，串成一個畫面就容易得多。

佳如（1A）→ 想著被雷劈的蓋斯（2A）→ 搭飛機嫁到英國（3A）→ …
→ 楊柳溪邊（6A）→ 溪裡的鱷魚（7A）→ 嚇到的乃亞克（8A）

6A 的「溪」與 7A 的「鱷」共用同一個溪邊場景，兩族天然相鄰。
`scene` 與 `sceneNext` 欄位記錄這條線，供教學畫面依序播放。

#### 5.2.3 mnemonics-elements.json

族口訣負責「順序」，但學生還需要能單獨認出某一個元素。個別掛鉤補這一塊：

```json
{
  "z": 11,
  "imagery": "廚房餐桌上的鹽罐，倒出來的白色顆粒。",
  "hook": "食鹽就是氯化鈉"
}
```

因為口訣已經處理了諧音，個別條目**不需要**再寫諧音欄位，只需要圖像與一句話 hook。
這使得後續由 sub-agent 批次填充的工作量與 token 成本都顯著下降。

風格要求（供 sub-agent 遵循）：

- 使用台灣繁體中文語感，避免中國大陸用語
- 圖像必須是國中生日常生活中真的看得到的東西
- `hook` 控制在 12 字以內
- 不使用暴力、性、政治或任何不適合未成年人的聯想
- 不與所屬族的口訣場景衝突

### 5.3 stages.json

階段以**族**為單位，不是原子序範圍。順序依「國中出現頻率」而非週期表版面順序排列，
讓學生先拿下最常考、性質最鮮明的四族。

| 階段 | 名稱 | 內容 | 口訣 | 元素數 |
|---|---|---|---|---|
| 1 | 新生入隊 | 1A 鹼金族 | 請你讓佳如設法 | 7 |
| 2 | 板凳待命 | 2A 鹼土金族 | 媲美蓋斯被雷 | 6 |
| 3 | 先發登場 | 7A 鹵素 | 浮綠秀點鱷 | 5 |
| 4 | 快攻上手 | 8A 惰性氣體 | 害乃亞克先動 | 6 |
| 5 | 主力攻手 | 3A + 4A | 朋屢嫁英他／嘆息著西遷 | 10 |
| 6 | 隊上王牌 | 5A + 6A | 但你身體病／楊柳溪地破 | 10 |
| 7 | 全國大賽 | 常見過渡金屬 | 無口訣，走圖像法 | 10 |

合計 54 個元素。

**階段 7 的過渡金屬**：Fe 鐵、Cu 銅、Zn 鋅、Ag 銀、Au 金、Hg 汞、Cr 鉻、Mn 錳、
Ni 鎳、Pt 鉑。只收國中真的會考的，不背整列。這十個學生日常生活就熟悉
（鐵鎚、銅線、金牌、溫度計），用圖像記憶法比硬編口訣有效。

**解鎖規則（單一公式）**：前一階段有 80%（無條件進位）的元素進入盒 3 以上。
綁在「進入盒 3」而不是「答對過」——答對一次不代表記住，盒 3 代表至少跨過一天還記得。

`elements.json` 仍收錄全部 118 個元素，供 §7.3 的完整週期表查詢使用。
階段只決定「測驗會出哪些」，不限制「可以查哪些」。

### 5.4 localStorage schema

```js
{
  schemaVersion: 1,
  updatedAt: 1755950000000,
  settings: {
    theme: "default",
    soundOn: true,
    customImages: { background: null, rewardCard: null }  // IndexedDB key
  },
  unlockedStages: [1],
  cards: {
    "11": {
      box: 2,              // 1..5
      nextDue: 1756036400000,
      lastSeen: 1755950000000,
      streak: 1,           // 連續答對次數
      correct: 3,
      wrong: 1,
      avgMs: 4200
    }
  },
  stats: {
    totalAnswered: 0,
    totalCorrect: 0,
    cheerPoints: 0,
    bestRally: 0,
    sessions: []           // { date, answered, correct } 保留最近 30 筆
  }
}
```

`schemaVersion` 是硬性要求。任何資料結構變動都必須附帶 migration 函式。
**絕不允許因為程式改版而清空學生累積的進度。**

## 6. 核心模組

### 6.1 store.js

單一職責：讀寫 localStorage、執行 schema migration、提供不可變的狀態快照。
其他模組一律透過 store 存取狀態，不直接碰 localStorage。

讀取時若 `schemaVersion` 低於目前版本，依序套用 migration 後寫回。
若資料損毀無法解析，備份原始字串到 `pq_backup_<timestamp>` 後才初始化新狀態。

### 6.2 scheduler.js — Leitner 五盒

| 盒 | 間隔 |
|---|---|
| 1 | 立即（同一輪內重出） |
| 2 | 1 天 |
| 3 | 3 天 |
| 4 | 7 天 |
| 5 | 14 天 |

答對升一盒（盒 5 為上限），**答錯直接掉回盒 1**，不是退一盒。記錯的東西需要從頭重建。

**為何選 Leitner 而非 SM-2**：國中生使用頻率不穩定，可能三天沒開 App。SM-2 的難度係數（ease factor）在低頻、樣本少的情況下容易失準。Leitner 的離散盒子在稀疏使用下行為可預測，而且「盒子」概念本身可直接視覺化成遊戲進度（盒 1 是板凳、盒 5 是先發），讓演算法與獎勵機制共用同一個心智模型——學生看得懂自己為什麼在這個位置。

反應時間額外記錄於 `avgMs`。答對但耗時超過 8 秒的題目，升盒但同時標記為「猶豫」，在弱項抽題時仍有較高權重。想很久才答對，代表還沒真的記熟。

### 6.3 quiz.js — 出題器

七種題型。前五種測「單一元素」，後兩種測「族的順序」——這是按族背誦特有的，
也是最貼近真實考題的部分。

1. 符號 → 中文名（四選一）
2. 中文名 → 符號（四選一）
3. 原子序 → 元素（四選一）
4. 符號填空（鍵入。判定時忽略大小寫與前後空白，答對後在回饋中顯示正確寫法，
   並提示元素符號的大小寫規則：首字母大寫、第二字母小寫）
5. 週期表定位（在互動式週期表上點出位置）
6. **口訣填空**：給「請你□佳如設法」，問缺的字或該字對應的元素
7. **族別判定**：給一個元素，問屬於哪一族；或問同族的下一個元素是誰

題型 6、7 直接從 `mnemonics-groups.json` 的 `mapping` 欄位生成，不需額外出題資料。

抽題來源權重：**到期複習 60% / 弱項加強 25% / 新元素 15%**。
若到期題不足，缺額依序由弱項與新元素補上。

**干擾選項設計**（決定題目品質的關鍵）：三個干擾項優先取自
同族 → 同週期 → 符號形近（Na/Mg、Fe/Fl、Cu/Ca、Co/Cr）→ 中文字形近（鈉/鈣、氯/氮）。
不使用隨機抽樣，否則學生用刪去法就能過關，等於沒有測到辨識能力。

### 6.4 progress.js

計算階段解鎖、產生統計、判定弱項清單。純函式，輸入狀態輸出結論。

## 7. 遊戲層與週期表查詢

### 7.1 連段機制（rally.js）

一題等於一次觸球。答對推進連段：一傳 → 舉球 → 扣球。
**連續答對 3 題得 1 分**，答錯掉球、連段歸零。
一局結束條件：得 25 分，或作答滿 20 題。

**賽末點機制**：當比分達 22 分以上，系統改抽學生的弱項題，答對給雙倍應援值。
把最難的題目放在動機最高的那一刻。

### 7.2 獎勵（rewards.js）

得分轉換為「應援值」（cheerPoints），用途：

- 解鎖配色主題
- 解鎖圖鑑卡面樣式

**應援值只解鎖外觀，不解鎖學習內容。** 階段解鎖完全由 §5.3 的學習條件決定。
把學習內容鎖在點數後面，會讓沒時間刷分的學生卡住，違背工具本身的目的。

應援值只能累積、不可消耗歸零——這是給國中生的學習工具，不是要製造焦慮的抽卡遊戲。

### 7.3 完整週期表查詢（screen-table.js）

學生需要一個隨時可查的完整對照表，不受階段解鎖限制。

`components/periodic-table.js` 是一個可重用的互動式週期表元件，
同時服務查詢畫面與題型 5 的答題介面：

- 標準 18 欄版面，含鑭系與錒系另列
- 每格顯示原子序、符號、中文名
- 依 `category` 著色，一眼看出金屬／非金屬／惰性氣體分區
- 點任一格 → 展開該元素的資料、所屬族口訣（該字高亮）、圖像掛鉤、目前所在的盒
- 「按族高亮」模式：選擇一族，整條直行亮起並顯示口訣，方便對照複誦
- 手機上以水平捲動容納 18 欄，不縮小到看不清

這個元件必須自行以 HTML/CSS Grid 實作，不使用來源圖片（見 §8.1）。

## 8. 主題與視覺

### 8.1 版權界線（硬性規範）

專案會發布到 GitHub Pages，屬於公開發布，所有素材都必須經得起檢視。

**動漫與偶像團體**

《排球少年》與 NCT WISH 皆為受版權保護的作品。本專案：

- **不使用**任何官方圖片、角色立繪、照片、logo、字體、音樂
- **不使用**特定角色姓名、隊伍名稱、成員姓名
- **可使用**排球運動的通用術語（一傳、舉球、扣球、攔網、賽末點）與通用的應援文化概念
- 所有視覺素材由 CSS 與 SVG 自行繪製：球場、球網、球體軌跡、應援棒光點、得分特效

**口訣素材（`元素表口訣.jpg`，作者 @酪梨寶）**

- **可使用**：八族口訣文字本身。短的事實性記憶句，且已由使用者提供採用。
- **可使用**：場景概念（佳如、被雷劈的蓋斯、飛機、楊柳溪、鱷魚、乃亞克）。
  圖像記憶法的價值在於畫面聯想，這些聯想概念是口訣的一部分。
- **不可使用**：原圖的插畫本身。那是作者的原創畫作且帶有浮水印。
  所有插圖由本專案依相同場景概念**自行重畫**，並與遊戲的整體視覺風格統一。
- README 中標註口訣來源致謝。

### 8.2 配色主題

`css/tokens.css` 以 CSS 自訂屬性定義所有色彩，切換主題只改 token。
預設提供數組配色，實際色值由學生在設定頁確認與調整——不預先硬寫任何宣稱為「官方應援色」的色值。

### 8.3 學生自訂圖片

設定頁提供「換成自己的圖」：從相簿選圖作為背景與獎勵卡面。
圖片經 canvas 壓縮後存入 IndexedDB，**不上傳、不外傳**。
提供一鍵還原預設。

## 9. 測試策略

只對 `js/core/` 寫自動化測試，UI 以人眼驗證。

理由：排程演算法與出題器屬於「錯了也能跑，但會默默損害學習成效且看不出來」的類型——盒子排程差一天、干擾選項抽到不合理的元素，畫面上完全正常。這類 bug 必須靠測試抓。UI 則相反，錯了一眼就看得到。

測試以瀏覽器原生執行：`tests/index.html` 載入測試檔，用最小的自製 assert 函式，不安裝任何框架（環境無 node）。

必測項目：

- 答對升盒、答錯歸零、盒 5 上限
- `nextDue` 計算正確
- 到期題篩選在跨日邊界的行為
- 抽題權重在各種題庫狀態下的分配（含到期題不足時的補位）
- 干擾選項不重複、不含正解、優先序正確
- 階段解鎖條件判定
- schema migration 不遺失既有進度

## 10. 版本控管與部署

- 本機 git repo，remote 指向 GitHub
- `main` 分支保持隨時可用；功能在 `feat/<name>` 完成並驗證後併入
- GitHub Pages 由 `main` 提供服務，學生的 iPhone 重整即取得更新
- 開發驗證用 `python3 -m http.server 8000`
- Service Worker 需妥善處理快取版本，避免學生拿到舊版卡住

## 11. 開發流程：token 預算與續作

這是需求 7 的落實，與功能設計同等重要。

### 11.1 PROGRESS.md

`docs/PROGRESS.md` 是續作的單一真相來源，每個 task 結束後更新：

```markdown
# 進度
最後更新：YYYY-MM-DD
目前位置：Phase 2 / Task 2.3

## 已完成
- [x] 1.1 專案骨架與 PWA 外殼 (abc1234)
- [x] 1.2 elements.json 建置 (def5678)

## 下一步
- [ ] 2.3 出題器干擾選項邏輯

## 待決事項
- 個別元素的圖像掛鉤是否需要更口語？等學生試用階段 1 後回饋
```

### 11.2 中斷與續作規則

**一個 task = 一個 sub-agent = 一個 commit。**

Task 顆粒度必須控制在單一 sub-agent 一次能完成的範圍內。
每個 task 結束就 commit 並更新 PROGRESS.md，因此中斷點永遠落在 commit 邊界，
不會留下半完成的狀態。

隔天續作只需一句「繼續」：讀 `docs/PROGRESS.md` 加上 `git log --oneline -10`
即可接續，無須重讀整個程式碼庫。

### 11.3 Sub-agent 分派

| 工作類型 | 模型 | 理由 |
|---|---|---|
| mnemonics-elements.json 批次填充 | Haiku | 有範本、格式固定、量大 |
| elements.json 資料建置 | Haiku | 純查表填值，無需推理 |
| UI 畫面、CSS、SVG 素材 | Sonnet | 一般實作 |
| core 模組、核心測試 | Sonnet | 邏輯正確性要求高 |
| 架構決策、整合、review、維護 PROGRESS | Opus（主 session） | 需要全局脈絡 |

Sub-agent 不繼承對話脈絡。因此實作計畫中每個 task 都必須自包含：
明確列出要讀哪些檔、產出哪些檔、驗收標準為何。

### 11.4 內容生產節奏

**族口訣已完備**，由使用者提供且逐字核對過，不需要生成——這消除了原先預估中
最大且最不確定的一塊 token 支出。

剩下的內容工作是 `mnemonics-elements.json` 的個別圖像掛鉤，做法如下：

1. 主 session 親自撰寫**階段 1（1A 鹼金族，7 個元素）**的圖像與 hook
2. 交給學生實際使用，確認風格與難易度合適
3. 以這 7 組為範本樣本，派 Haiku sub-agent **依階段**分批補齊其餘

先驗證再量產。圖像好不好記非常主觀，未經驗證就大量生產，整批重做的風險很高。
依階段分批也讓內容生產與學生的實際進度對齊——學生還沒解鎖的階段可以晚點再補。

`elements.json`（118 筆客觀資料）不受此節奏限制，一次建置完成，
因為它是純查表工作且後續所有功能都依賴它。

## 12. 非目標（YAGNI）

明確排除，避免範圍蔓延：

- 帳號系統、雲端同步、多使用者
- 家長／教師後台與報表
- 社群功能、排行榜、好友對戰
- 元素性質的深入化學教學（反應式、電子組態）——本專案只處理「記住」
- App Store 上架
- 音效與配樂（第一版先不做，`soundOn` 設定預留欄位）
- 深色／淺色自動切換（配色主題已涵蓋此需求）
